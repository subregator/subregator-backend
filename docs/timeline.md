# Resource timeline and imported history

`GET /api/v1/timeline?resource=1.1.1.0%2F24&limit=50` and MCP `resource_timeline` with `filters={"resource":"1.1.1.0/24","limit":"50"}` combine existing listing/asking-price events and approved network observations. This is a cached-only read. Known exact public IPv4/IPv6 prefixes are required; current provider disclosure, historical-publication restrictions and check approval are reapplied on every page. Hidden and unknown prefixes return empty results. AbuseIPDB, IRR and ZEN histories remain explicitly unavailable; their absence is not clearance.

Follow `next_cursor` as the next request's `cursor`. Pages order by listing observation time or network ingestion time, then listing/network kind and source row ID. Source event dates stay separate and do not reorder late imports. A cursor captures both streams' committed high-water IDs and binds the prefix and effective provider/check allowlists. New rows belong to a new pagination pass. A policy change rejects an existing cursor; restart from page one. Listing data predates dedicated ingestion/provenance tracking: `ingested_at` is null and legacy SQLite imports cannot reliably be distinguished from original listing observations. These limitations are explicit in `semantics`; no ingestion timestamp is invented. `tracking_started_at`, `archive_started_at`, scoped windows, gaps and per-entry evidence links delimit what was actually recorded. No history before tracking is implied.

## Optional background imports

`SUBREGATOR_HISTORICAL_CHECKS` / `-historical-checks` is a separate, empty-by-default comma-separated approval list: `routing_history`, `allocation_history`, `transfer_history`, `registration_history`. It authorizes collection, indefinite retention and public display of the selected normalized history. Confirm source terms and capacity before enabling it. It does not change the existing `SUBREGATOR_HISTORY_CHECKS` gate or obtain source permission. `SUBREGATOR_NETWORK=false` prevents new requests. Do not enable these additional queues while the basic collectors are capacity constrained.

The existing single worker adds one bounded queue per enabled check, sharing upstream budgets, concurrency, cancellation, failure backoff and source Retry-After. Only currently published eligible prefixes are collected. Routing and allocation request the previous seven complete UTC days; no unbounded backfill or version traversal is started. Routing retains the existing `max_rows=300` upstream soft bound. Transfer history has no supported source pagination/window parameter, so one bounded response is projected; registry history retains version/date metadata only, never raw objects, references, names, contacts or addresses. Registry history is RIPE Database only. Each response retains at most 300 normalized records and the existing 1 MiB HTTP bound; archive evidence remains capped at 64 KiB. Truncation is explicit, no hidden next-page loop runs, and successful transport never establishes complete historical coverage. Invalid or oversized responses become gaps rather than empty clean histories. Source corrections yield distinct snapshots.

Imported historical rows have `origin: imported_history` and `event: historical_snapshot`, separate collection/ingestion times, requested/source windows and record-level exact/covering/contained scope. Source dates belong to the records. A covering transfer remains a statement about that covering block. Imports never infer private ownership, tenant changes, historical RPKI validity or complaint resolution. Repeating identical normalized evidence in the same requested scope/window is idempotent despite a later poll time; changed evidence is appended. Historical snapshots are not comparable baselines for current-state changes.

Source rights, live payload compatibility beyond synthetic documented shapes, production migration/capacity and backup/restore are separate checks. Finite retention is not implemented, as with BE-10; sources requiring expiry must remain disabled. Existing listing imports lack exact per-row provenance and are not relabelled as historical source events.
