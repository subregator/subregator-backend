## Credential and evidence handling

- Existing optional IPinfo credentials are referenced only by environment-variable name. `SUBREGATOR_DATABASE_URL` is storage configuration, not a public source credential. No values belong in this inventory, issues, URLs, tests or logs.
- For a new authenticated source, record the credential's operational location and owner after provisioning, without its value; no new secret-store path is invented here.
- Record approval date, source, allowed fields, display/retention limits and refresh entitlement in the operational policy record when evidence becomes available. This document records unknowns; it does not grant permission or silently disable existing integrations.
- Respect current provider publication rules in live offers, correlations, history, exports and external lookups. Never reconstruct hidden prefixes.

BE-01's inventory deliverable is complete when these unknowns are explicit and each integration has an actionable access gate. Obtaining third-party approval remains a blocker on the relevant integration, not evidence that it is already usable.

## BE-07 pilot — 2026-11-25

The selected minimal adapter uses the existing hosted IRRexplorer JSON API, not a self-hosted IRR stack. One IPv4 and one IPv6 prefix request plus metadata returned HTTP 200 without authentication. The Go normalizer accepted both captured shapes; IPv6 returned a containing route rather than an exact object, and old registry update dates remained stale. This verifies those responses only. No numeric quota, public API redistribution or retention grant was confirmed. The new `SUBREGATOR_IRR` gate defaults to false, publishes `not_configured`, and suppresses source collection and retained IRR output until the operator conditions are confirmed. See [IRR contract and pilot](irr.md). No operator message was sent.

## BE-08 account gate before credential provision — 2026-11-25

An optional fixed-endpoint AbuseIPDB adapter now normalizes check-block summaries, but no configured AbuseIPDB key was found by key-name checks of the environment and original local environment configuration. No values were printed and no authenticated pilot was performed. `SUBREGATOR_ABUSEIPDB` defaults to false; a key alone does not enable collection or cached publication. The provisional request scope is current IPv4 /24 or longer with a fixed 30-day window; IPv6 and broader scope remain explicitly unsupported pending account validation. Plan, quota, public display and cache-retention conditions are unconfirmed. No operator message, purchase, source report or deletion was made. See [abuse contract](abuse.md) for limits, source-time semantics, a computed capacity floor and remaining work.

## BE-08 authenticated pilot — 2026-11-25

The owner supplied a key for evaluation; it was used transiently and not copied into source, environment files, issues or command-line arguments. Response headers confirmed 100 check-block requests/day. Thirteen limited requests, including validation failures and one through the actual Go collector, left 87 available. IPv4 /24, /30, /31 and IPv6 /120, /127 returned complete requested ranges; /32 and /128 were rejected as single hosts. IPv4 /23 and 31 days hit plan limits. IPv6 /119 succeeded but remains outside the local 256-address work bound. The normalizer now supports IPv4 /24–/31 and IPv6 /120–/127 without enumeration. Published [terms](https://www.abuseipdb.com/legal.html) distinguish non-commercial/evaluation use and commercial/data redistribution; public aggregator and cache-retention permission is not established by a valid key. The source stays off, no account upgrade/contact/publishing occurred, and production credential placement remains unprovisioned. See [pilot evidence](abuse.md). Earlier no-key entries above are dated snapshots.
